## 财务规则

- 金额按整数分保存，CAD/CNY 分开统计；没有伪造汇率，也不进行隐式换算。
- 初始余额是快照，不产生收入或消费。
- 信用卡总欠款和每期账单剩余独立保存；新消费不改变已出账金额。
- 退款增加资产或减少信用卡欠款，在退款所在月份抵减支出，不伪装成收入；账单受退款影响时按银行实际结果核对。
- 还款从资产账户转入信用卡，按最早到期账单分配，超额保留为未分配还款。费用单独记支出。
- 实际到期日保存完整年月日，逾期不会滚动到下个月。首页按到期日期排序。同一卡同一到期日期不允许重复建账单，已有账单使用“核对账单”更正。
- 对账保存系统旧值、实际新值及说明，采用版本检查，不把未知差额伪造成收入/消费。
- 账户起始/最新对账日之前的交易只补历史，不再次影响余额。同一天的旧交易需要勾选“只补历史”，因为银行当前余额已可能包含它。
- 撤销保留原记录；最新对账之前的交易撤销不再次改变当前余额。已手动更正账单后，不能自动撤销更正之前的相关还款，需要重新核对。
- 可支配金额＝现金资产−学费/生活/储蓄预留−未来 30 天与逾期的未还账单。预留项不要重复放入还款资金。
- 缺少账单的卡会提示金额可能偏高；未出账消费不是当前已知账单，不当作已确认到期金额。
- 统计明确标记记录区间及完整性未确认；零记录不等于零消费。

## 异常与隐私

所有写入通过数据库 RPC，验证 `auth.uid()` 并在一次事务中执行；按用户加锁，所有账户引用均验证归属。浏览器仅获自己数据的 SELECT 权限，无法直接改余额。

首页快照和未确认请求仅缓存于当前标签页的 sessionStorage，并按用户 ID 隔离；退出/账号切换清理缓存。迟到的旧账号响应不能写回新账号页面。浏览器会话由 Supabase SDK 管理，不再使用自定义 localStorage 身份。

请求限时 15 秒；网络失败不算成功。结果未知时保留原请求及幂等键，“查询并重试”重放同一请求，数据库返回原结果而不重复扣款。明确校验失败保留表单供修改。已保存但刷新失败会单独提示。

演示纯本地、只读、虚构，不读写云端财务数据。新版不调用 Gemini，不发送财务备注给 AI。

## 旧 MongoDB 账如何处理

本次不会自动迁移真实财务数据，也不会删除 MongoDB 数据。建议先将原库备份放在 Git 忽略的 `private-data/` 目录，在新版以已核实的当前余额开始。

历史搬迁需要显式用户映射和单独预览：

1. 旧身份字符串不能作为新用户的登录凭证；由你确认其对应的 Supabase 用户。
2. 旧账户余额经银行核实后建立起始快照，不根据不完整交易重新计算。
3. 旧转账没有完整目标与币种，必须标为待核实；不能自动重新执行。
4. AI 模拟入账只作为候选异常，不能按金额为 10 自动删除。
5. 如需导入历史，必须使用稳定的外部交易 ID 对应幂等键，并走“只补历史”逻辑；当前界面支持逐笔补录，没有实现批量 MongoDB 导入。
